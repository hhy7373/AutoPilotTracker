# AutoPilotLog v0.4.1

## 新增

- 增加来源优先级、冲突备注、核验人和系统/车型/版本搭载关系的数据模型。
- 增加管理员邮箱密码登录和 Magic Link 登录入口。
- 管理后台默认打开 `Unverified` 行程审核队列。
- 审核队列展示版本、车型配置、里程、道路类型、人工干预详情和证据数量。
- 管理员可在权限校验后获取证据图片的 5 分钟私有签名链接。
- 管理员目录维护面板支持为系统、版本和车型选择已核验来源，并在发布前强制关联来源证据。
- 云端投稿表单改为读取真实公开目录，按“系统 → 车辆品牌 → 车型配置”联动，软件版本同步显示已核验版本。

## 改进

- 公开目录接口继续只读取已核验/已发布记录；方案商候选数据不会因抓取到官网入口而自动发布。
- 管理员审核状态变更写入审计日志。
- 增加 `docs/CATALOG_DATA_POLICY.md`，明确官网优先、媒体交叉验证和人工核验规则。
- 增加 `docs/CATALOG_RESEARCH_V041.md`，记录已打开的官方来源、已确认事实和仍保持草稿的版本/硬件/配置声明。
- 公开系统接口不再返回没有 `primary_source_id` 的目录记录；版本和车型接口同时要求已核验状态、来源证据和已核验系统。
- 管理员审核页面增加私有证据查看入口，浏览器只接收短时签名 URL。
- 生产迁移缺失时，车型目录 API 返回明确的迁移提示，便于部署诊断。
- 新增 `npm run verify:production`，用于迁移后的 API、目录字段、来源表、搭载关系表和公开统计视图验收。
- 生产验收脚本额外检查官方证据目录的最小记录集，防止仅创建空表或仅发布系统名而误判字典完成。

## 数据库/API 变更

- 新增 `202609100001_v041_catalog_review_and_admin.sql`、`202609160001_v041_official_catalog_evidence.sql` 和 `202609100002_v041_public_catalog_views.sql`。
- 新增 `202609160001_v041_official_catalog_evidence.sql`：仅将官方页面直接支持的 ADS 4、第二代 VLA、马赫 VLA、NOP+、Xiaomi HAD、WRD 3.0 产品/方案以及车型搭载关系写入已核验目录；无精确官方 OTA 原文的旧样本继续保持草稿。
- 新增 `GET /api/admin/submissions/:id/evidence`。
- `GET /api/admin/submissions` 默认只返回 `unverified`，可用 `?status=` 切换审核状态。

## 隐私与安全

- 不保存或返回完整 VIN；公开响应不返回作者 ID 和 Storage 路径。
- 管理员权限仍由 Supabase JWT 的 `app_metadata.role=admin` 判断。
- 签名图片链接只返回给管理员，默认 300 秒过期。

## 验证结果与已知限制

- 已通过 `npm run build`、`npm run api:check` 和 `git diff --check`。
- 线上 API 健康检查通过；Supabase v0.4.1 迁移尚未在生产 SQL Editor 执行，目录接口在迁移完成前会保持空/不可用，避免草稿数据进入投稿选择项。
- 生产执行顺序为 `202609100001_v041_catalog_review_and_admin.sql` → `202609160001_v041_official_catalog_evidence.sql` → `202609100002_v041_public_catalog_views.sql`。
- 当前 `npm run verify:production` 结果：API 健康、来源表、公开统计视图和公开行程隐私边界通过；`vehicle_brand` 字段与 `system_vehicle_compatibility` 表尚不存在，因此车型目录和完整审核闭环仍未通过。
- 2026-09-12 再次验收：ECS 上的最新前端构建和 API 已部署，`/api/health`、公开行程和隐私字段检查通过；车型目录仍因生产库缺少 `vehicle_brand` 返回迁移提示。Supabase 控制台会话当前不可用，尚未执行 v0.4.1 三条 SQL，不能将管理员审核闭环标记为完成。
- 当前官方入口已登记，但具体 OTA、车型配置和搭载关系仍须管理员逐条打开原文核验；未核验记录不得发布。
- 官方证据迁移只发布同一页面直接支持的对象与搭载关系；华为逐车型、地平线、卓驭及缺少逐配置原文的记录继续为草稿。
- 当前公网仍为 HTTP，管理员登录和证据查看应在 HTTPS 配置完成后使用。
- ECS API 的实际部署目录为 `/opt/autopilotlog-api`；部署文档已按生产 systemd 配置修正更新命令。
- 补强数据库级公开边界：收紧旧版系统、版本和车型的宽松 RLS，直接访问 Supabase REST 也不能读取草稿；为现有车型生成待核验的搭载关系草稿，并允许管理员在后台维护搭载关系。
- 搭载关系和证据审核均增加管理员权限边界；搭载关系在发布前必须关联已核验来源。
- 公开版本统计进一步排除 `is_test=true` 的测试行程，即使测试记录误被发布，也不会进入社区里程、行程数、车辆数或事件统计。
- 公开车型接口、投稿校验和数据库公开 RLS 统一要求存在已核验/已发布的系统—车型搭载关系；仅“属于同一系统”不再足以进入投稿选择项。
- 公开行程详情和事件摘要视图同步排除 `is_test=true`，避免测试记录通过详情接口或事件摘要间接暴露。
- 公开行程和版本统计视图进一步要求行程存在已核验/已发布的车型搭载关系，管理员误发布的旧关联记录不会绕过搭载关系边界进入统计。
- 公开搭载关系的 RLS 和公开行程视图同时检查系统、车型、版本及其来源的发布状态，草稿目录不会通过关系表或公开视图间接暴露。
- 搭载关系和公开视图还校验车型所属系统与关系中的系统一致，避免跨系统误关联进入投稿或统计。
- 管理员搭载关系 API 同样校验车型、版本与关系的 `system_id` 一致，拒绝直接调用接口写入跨系统关系。
- 版本统计视图补齐车型来源核验条件，与公开行程和事件摘要保持一致的来源边界。
- 为避免车型表与搭载关系表互相触发 RLS 递归，目录公开判断改为固定 `search_path` 的只读 `SECURITY DEFINER` 函数；函数只返回布尔值，不返回目录数据。
- 同步更新阿里云部署说明和生产验收脚本，明确迁移后的公开行程、事件摘要、版本统计和车型选择均受搭载关系与测试数据隔离规则约束。
- 研究记录补充官方精确证据：华为 ADS 4 发布新闻、小鹏 P7/G6 的第二代 VLA 与图灵芯片信息、小米 SU7 的 Xiaomi HAD/700TOPS 信息、文远知行 WRD 3.0 ADAS 产品信息；具体 OTA 小版本和逐配置搭载关系仍保持草稿。
- 修正华为 ADS 主来源更新条件，使其与 ADS 4 官方发布新闻 URL 一致；公开事件摘要同步执行车型搭载关系过滤。
- 数据库 RLS、API 和公开视图进一步要求搭载关系本身关联已核验来源，并同时校验系统、版本和车型的目录发布状态。
- 修正版本统计的左连接条件：不匹配搭载关系的行程会被排除，但对应版本仍保留并显示 0 样本统计。
- 迁移会把没有精确来源证据的示例 OTA 记录保持为 `unverified`/`draft`，不再仅因旧种子数据携带 `verified` 状态而进入可投稿目录。

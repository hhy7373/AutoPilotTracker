# AutoPilotLog v0.4.1

## 新增

- 增加来源优先级、冲突备注、核验人和系统/车型/版本搭载关系的数据模型。
- 增加管理员邮箱密码登录和 Magic Link 登录入口。
- 管理后台默认打开 `Unverified` 行程审核队列。
- 审核队列展示版本、车型配置、里程、道路类型、人工干预详情和证据数量。
- 管理员可在权限校验后获取证据图片的 5 分钟私有签名链接。
- 管理员目录维护面板支持为系统、版本和车型选择已核验来源，并在发布前强制关联来源证据。
- 云端投稿表单改为读取真实公开目录，按“系统 → 车辆品牌 → 车型配置”联动，软件版本同步显示已核验版本。

## 改进

- 公开目录接口继续只读取已核验/已发布记录；方案商候选数据不会因抓取到官网入口而自动发布。
- 管理员审核状态变更写入审计日志。
- 增加 `docs/CATALOG_DATA_POLICY.md`，明确官网优先、媒体交叉验证和人工核验规则。
- 增加 `docs/CATALOG_RESEARCH_V041.md`，记录已打开的官方来源、已确认事实和仍保持草稿的版本/硬件/配置声明。
- 公开系统接口不再返回没有 `primary_source_id` 的目录记录；版本和车型接口同时要求已核验状态、来源证据和已核验系统。
- 管理员审核页面增加私有证据查看入口，浏览器只接收短时签名 URL。
- 生产迁移缺失时，车型目录 API 返回明确的迁移提示，便于部署诊断。
- 新增 `npm run verify:production`，用于迁移后的 API、目录字段、来源表、搭载关系表和公开统计视图验收。

## 数据库/API 变更

- 新增 `202609100001_v041_catalog_review_and_admin.sql` 和 `202609100002_v041_public_catalog_views.sql`。
- 新增 `GET /api/admin/submissions/:id/evidence`。
- `GET /api/admin/submissions` 默认只返回 `unverified`，可用 `?status=` 切换审核状态。

## 隐私与安全

- 不保存或返回完整 VIN；公开响应不返回作者 ID 和 Storage 路径。
- 管理员权限仍由 Supabase JWT 的 `app_metadata.role=admin` 判断。
- 签名图片链接只返回给管理员，默认 300 秒过期。

## 验证结果与已知限制

- 已通过 `npm run build`、`npm run api:check` 和 `git diff --check`。
- 线上 API 健康检查通过；Supabase v0.4.1 迁移尚未在生产 SQL Editor 执行，目录接口在迁移完成前会保持空/不可用，避免草稿数据进入投稿选择项。
- 生产执行顺序为先执行 `202609100001_v041_catalog_review_and_admin.sql`，再执行 `202609100002_v041_public_catalog_views.sql`。
- 当前 `npm run verify:production` 结果：API 健康、来源表、公开统计视图和公开行程隐私边界通过；`vehicle_brand` 字段与 `system_vehicle_compatibility` 表尚不存在，因此车型目录和完整审核闭环仍未通过。
- 2026-09-12 再次验收：ECS 上的最新前端构建和 API 已部署，`/api/health`、公开行程和隐私字段检查通过；车型目录仍因生产库缺少 `vehicle_brand` 返回迁移提示。Supabase 控制台会话当前不可用，尚未执行两条 v0.4.1 SQL，不能将管理员审核闭环标记为完成。
- 当前官方入口已登记，但具体 OTA、车型配置和搭载关系仍须管理员逐条打开原文核验；未核验记录不得发布。
- 当前公网仍为 HTTP，管理员登录和证据查看应在 HTTPS 配置完成后使用。
- ECS API 的实际部署目录为 `/opt/autopilotlog-api`；部署文档已按生产 systemd 配置修正更新命令。
- 补强数据库级公开边界：收紧旧版系统、版本和车型的宽松 RLS，直接访问 Supabase REST 也不能读取草稿；为现有车型生成待核验的搭载关系草稿，并允许管理员在后台维护搭载关系。
- 搭载关系和证据审核均增加管理员权限边界；搭载关系在发布前必须关联已核验来源。
